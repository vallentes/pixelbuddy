# PixelBuddy architecture

Free desktop pets (Windows + macOS) on Tauri 2. Supported by donations (Buy Me a Coffee, Revolut); there is no licensing.

```
                     +------------------------- Rust core --------------------------+
 settings window --->| commands -> pets/settings -> SQLite                          |
 (React + voice      | SystemMonitor (idle, fullscreen) -> events                   |
  service)           | ReactionBus <- Twitch EventSub (tokens in OS keychain)       |
 pet windows ------->|   \-> overlay server 127.0.0.1 (SSE) -> OBS                  |
 (canvas, 1/pet)     | voice model download -> pbmodel:// protocol                  |
                     +--------------------------------------------------------------+
        pet windows <--- pet://presence / pet://social events ---> pet windows
```

* **One small transparent window per pet.** Borderless, always on top, click-through on transparent pixels. Each window runs its own brain (behavior state machine), motion (walking, gravity, throws with wall bounces) and renderer, and moves itself.
* **Two art styles.** HD: a vector rig (pose per state, eased at 60 fps, props and particles). Pixel: procedural 32x32 sprite sheets. All art is original and generated by code.
* **Talking.** `engine/chatter.ts` + `engine/lines.ts` hold per-personality lines and two-part jokes. Voices: natural (Kokoro-82M, generated in the main window, model downloaded once by Rust and served via `pbmodel://`), babble (WebAudio) or the system voice. Bubbles wait for the audio to start and type at the speed of speech.
* **Pets together.** Windows broadcast presence (position, state) a few times a second. The pet with the lower id invites a neighbor; both run the same seeded script (`engine/social.ts`) for their role: conversations, tag, high-fives, pranks, dance-offs, duets, joke-offs, copycat, magic shows, naps.
* **Touch.** Click zones (nose, head, ears, belly, feet, tail), press-and-hold hugs, tail pulls, double-click tricks, tickling with the cursor, drag and throw.
* **Streaming.** Local overlay server (Host-checked, loopback only) with SSE; optional Twitch device-code login and EventSub reactions.
